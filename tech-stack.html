01项目是什么

玩法定位与 MVP 内容预算 · 详见 01 / 02

一局完整的探案推理

玩家在固定案件中探索场景、收集证据，用自由文本审讯 AI 扮演的嫌疑人；NPC 可以逐层隐瞒秘密，玩家需要用不同证据逐层突破谎言链，查看人物关系图与时间线，最终提交「凶手 / 凶器 / 动机 / 作案过程」的结构化指控。判定由确定性规则完成，给出正确、部分正确或错误，并展示完整复盘。

MVP 是毕业设计交付物：优先 1920×1080 桌面端、单人无账号（匿名 Cookie 识别访问者），一条无招供的正确通关路径必须存在。

为什么它不只是「套壳大模型」

游戏事实全部由程序持有：证据、谎言层级、情绪与数值、披露时机都在数据库与规则引擎里。LLM 无权改变任何游戏事实，只负责把「程序获准的说法」表达得像这个角色——可解释的分层谎言与程序控制的事实披露是本项目的核心设计。

因此整个系统不依赖模型涌现能力来「当裁判」：评分、状态推进、披露、存档全部可复现、可测试。

玩法循环一轮游戏 = 探索 → 审讯 → 指控 → 复盘

02技术栈总览

每层选型 + 一句话理由 · 版本与供应商以最终实施为准

前端FRONTEND
  • Vue 3 + TypeScriptSPA 单页应用，Composition API，类型安全贯穿组件与 Pinia Store。
  • Element PlusUI 组件库：抽屉、时间线、标签页、骨架屏等案卷工作台组件。
  • ECharts人物关系图（graph 系列）与时间线（散点 / 区间带 / custom 系列）。
  • Pinia3 个 Setup Store：game / conversation / workspace。
  • Vue Routerhistory 模式，路由表完整定义。
  • 原生 fetch不做请求缓存框架；对话生成状态用 1.5 秒轮询。
  • 原生 CSSgrid 布局 + 主题变量，深色「侦探档案工作台」配色；动效只用 CSS 过渡。
未引入：axios、WebSocket 客户端、Tailwind、动效库。构建工具文档未指定。
后端BACKEND
  • Python + FastAPI模块化单体（非微服务），入口 backend.main:app。
  • Uvicorn单异步进程 ASGI 服务器，开发态 --reload。
  • SQLAlchemyORM + Session 事务边界；不引入 Unit of Work 框架。
  • Pydanticapi/schemas/ 请求 / 响应模型与校验。
  • Alembic数据库迁移：alembic.ini + migrations/versions/。
  • 纯函数领域层状态机用标准库 Enum + dataclass 实现，不用第三方状态机库。
分层固定为 api / application / domain / infrastructure 四层；离线导入 CLI import_case.py 负责案件发布。
数据库DATABASE
  • PostgreSQL（建议基线）以 PG 18 为能力参照；关系表 + JSONB。MySQL 8.4 为备选，实施时二选一。
  • 21 张表静态案件 9 + 运行状态 8 + 对话 / 计量 / 摘要 4。
  • 复合外键 + 部分唯一索引复合外键锁定「同局同版本」；部分唯一索引保证同局最多一个生成中的 NPC 轮次。
  • 事务隔离写入 READ COMMITTED + 行锁；恢复读取 REPEATABLE READ。
明确不引入 Redis、向量数据库、消息队列；SQLite 不能替代行锁 / 隔离级别验收，不用于测试。
AI / LLM 接入AI LAYER
  • 自研 LLM Gateway类名 LLMClient，全项目唯一可发起模型请求的位置，主备双模型路由。
  • OpenAI 兼容 API供应商与具体模型未定，仅约定接口风格；密钥只存在于后端。
  • 结构化输出JSON Schema 约束，最小输出 {"text": string}，拒绝工具调用与额外字段。
  • 自研三级记忆近 6 轮全文 + 程序式摘要 + 结构化 NPC 状态；不用向量检索。
  • 受限编排AgentManager 白名单角色路由（NPC / HOST / REVIEW），生成需校验 GenerationPermit。
不用 LangChain / LangGraph 等 Agent 框架（未引入，明确不建通用 Agent 平台）；RAG / Embedding 明确不进 MVP；Judge Agent 已取消，评分归规则引擎。
API 与通信API & REALTIME
  • 纯 REST基础路径 /api/v1，约 32 个资源化端点，GET 一律只读。
  • HTTP 轮询无 WebSocket / SSE；前端建议 1.5 秒轮询会话五态（PREPARING / GENERATING / COMPLETED / FALLBACK / STALE）。
  • 幂等与并发Idempotency-Key 请求头 + X-Expected-State-Version 乐观并发头 + 一次性效果键。
  • 统一错误外壳稳定错误码目录约 40 个；View<T> / ActionResult<T> 响应外壳；字段 snake_case。
SSE 实时推送与流式回复（打字机）只是后续增强提案，当前 API 不提供。
测试与质量QUALITY
  • pytest9 个 marker：unit / integration / agent / rule / state_machine / api / e2e / live_llm / performance，--strict-markers。
  • pytest-playwrightE2E 阶段真实启动 Vue、FastAPI 与目标数据库；真实模型评测需显式 RUN_LIVE_LLM_TESTS=1。
  • Ruffruff format --check + ruff check，配置集中在 pyproject.toml。
  • 用例编号体系U / R / SM / AG / IT / API / E2E 七族编号，固定回复模式下必须可完整通关。
pytest-cov 可选；前端单测框架（Vitest 等）文档未提及。
安全与部署SECURITY & OPS
  • 匿名 Cookie高熵令牌 + HttpOnly; Secure; SameSite=Lax，库中只存 SHA-256 摘要；无 JWT / OAuth。
  • 输入防线Origin 校验、请求体 64 KiB 上限、Cache-Control: no-store；模型输出严格 Schema + 内容双重校验。
  • 部署形态一个后端进程 + 一个数据库，前端静态部署、建议同源；配置走 .env（密钥仅后端持有）。
  • 备份与恢复每日一致性逻辑备份，RPO ≤ 24h、RTO 1 小时演练目标。
Docker / docker-compose / 反向代理文档未提及；12 类风险（R01 提示注入 ～ R12 数据库异常）全部按 P0 处置。
游戏内容与状态GAME CONTENT
  • 离线案件包backend/assets/cases/case_001/v1/case.json，版本化，经 CLI 导入后发布；运行时账号对静态表只读。
  • 自动存档会话级状态全部落库，状态版本号 state_version 乐观并发；恢复读取与写入隔离级别分离。
  • 复盘投影证据背包、关系图、时间线均为「玩家可见安全投影」，由证据引擎统一裁剪，不泄露未获准信息。

模块职责
Game Engine
application/game.py		用例编排、授权、幂等、事务边界；写用例的唯一事务持有者。
State Machine
domain/state_machine.py		9 个概念阶段、动作允许表、转换守卫；纯标准库实现。
Evidence Engine
domain/evidence.py		证据持有 / 引用校验、获批披露应用，背包 / 关系图 / 时间线的玩家可见安全投影。
Rule Engine
domain/rules.py		纯 Python 确定性规则：EVENT 白名单触发 → 数值先求和再截断 → 谎言击破 → 承认判定 → 披露 → 一次 PROGRESS；独立评分分支；一次性效果键去重。
谎言系统
domain/lies/		分层谎言状态与 LieChain 线性分链；程序选定表达策略组成 ResponsePlan，LLM 不得更换借口或扩大承认。
Agent Manager
application/agents.py		受限角色路由（NPC / HOST / REVIEW 白名单），校验 GenerationPermit 后调用唯一 Gateway；自身无 DB Session、无规则引用。
Memory Service
application/memory.py		三级记忆装配 build_context()、程序式摘要 summarize_history()、结构化状态更新；memory_epoch 标记授权段，授权变化即失效旧对话记忆。
Conversation Service
application/conversation.py		输出结构与内容双重校验，失败固定降级；不让另一个模型当审核员。
LLM Gateway
infrastructure/llm_client.py		全项目唯一模型请求出口：主备路由、超时、熔断、严格 JSON 校验、usage 归一化。
Case Service / Save-Load固定案件版本载入校验 / 一致快照装配与版本兼容检查。
generation.pyGame Engine 的表达生成子流程：占位、额度预留、DISPATCHING 条件抢占、计量结算、过期清理。
关键机制：双事务提交

事务 A 提交规则效果 → 事务外调用模型（调用期间不持有任何数据库锁）→ 事务 B 保存表达与用量。业务状态版本 state_version 与生成状态彼此分离，模型故障不会污染游戏事实。

04AI 接入方式

受限生成 · 可复现 · 详见 07 / 08 / 12 / 13

上下文预算（设计初值，待实测）

项预算
输入上限4,000 tokens
输出上限400 tokens
近期历史 + 摘要1,100 tokens（摘要 ≤ 300）
单轮问题建议500 tokens
整轮 deadline30 秒（待实测初值）

超出预算按程序裁剪，不靠模型自觉；输出超长按固定降级处理。

调用控制

  • 每个命令最多 1 次上游调用；显式重试 ≤ 2 次，SDK 自动重试设为 0。
  • 熔断：连续 3 次故障冷却 60 秒。
  • 本地并发信号量建议 4；主备双模型路由。
  • 所有调用计量入库（token 用量归一化），按会话结算。
  • HOST / REVIEW 默认由 Python 固定文本提供，按需才润色。
三级记忆每级都可程序化复现 · memory_epoch 控制授权失效
近 6 轮完整问答最近对话原文直接进入上下文
程序式摘录摘要每 4 轮增量触发，CAS 写入 summary_revision，不经模型
结构化 NPC 状态情绪 / 压力 / 信任 / 谎言层级，从数据库直读
为什么不用 RAG

MVP 记忆来源是结构化数据，按 NPC 权限直接筛选数据库记录即可，无向量检索或 embedding 调用——可解释、可测试、零额外成本。

05状态机与谎言系统

确定性内核 · 详见 05 / 06 / 08

会话状态机（9 阶段）6 个持久化阶段 + 3 个事务内瞬态
INIT→ INTRO→ INVESTIGATION→ INTERROGATION→ DEEP_INVESTIGATION→ ACCUSATION→ JUDGEMENT→ REVIEW→ FINISHED

绿色为持久化阶段；紫色虚线（INIT / INTRO / JUDGEMENT）为事务内瞬态，不落库。每个阶段有动作允许表与转换守卫，非法动作直接被 API 拒绝。

分层谎言状态（不可逆）

UNBROKEN→ BROKEN→ ADMITTED

每个谎言层级只能单向推进。玩家出示对应证据 → 状态机击破 → 程序更新承认判定与披露内容，模型只是「把这一步说出口」。

5 类表达策略（ResponsePlan）

DENY坚决否认
EVADE回避问题
REDIRECT转移话题
PARTIAL_ADMIT部分承认
FULL_ADMIT完全承认

由程序根据谎言层级、压力 / 信任数值选定策略并限定说法边界，LLM 在边界内润色表达。

对话生成状态（前端轮询）GET /conversations/{id} 五态
PREPARING→ GENERATING→ COMPLETED或 FALLBACK· STALE

降级路径固定：模型失败不影响规则效果，已提交的游戏事实保持一致。
