## 事务与存档

- 每个写请求一个短事务：先按 `(visitor_id, request_id)` 查幂等结果，再锁 `game_session` 行，
  锁内复查请求、当前入口、预期版本、阶段和目标，然后执行纯领域规则并写回差异。
- 同键同输入返回原状态码与原结果；同键异输入 409；业务拒绝也记录，同键重发返回同一拒绝。
  认证、归属和请求头错误不记录。
- 有效变化才写根事件并让 `state_version` 加一；纯重复（如再次出示同一证据）为 NOOP，版本不变。
- 存档就是关系表的最新提交：`game_session`、`player_evidence`、`npc_state`、`rule_effect`、
  事件日志和结案后的 `accusation`。没有第二份可写的完整 JSON 存档。
- 读取使用 REPEATABLE READ 只读事务，GET 不运行规则、不写库。
- 数据库连接或超时失败返回 503 `PERSISTENCE_UNAVAILABLE`（可重试）；约束冲突等程序错误返回 500。
  两者都整体回滚，前端只在服务器确认后显示成功。

## 与设计文档的差异

以下是为切片做的取舍，后续版本补齐时以第 09、10 篇为准：

- 静态表只保留切片用到的列。人物没有性格、语言风格、接触条件和链分组；证据没有种类和关键标记；
  案件版本没有 NPC 策略、初始状态、官方证据关联和时间线零点；会话没有模型预算列。
- 切片 JSON 只为可审讯角色提供姓名和身份；另外三名嫌疑人的人物行由指控候选标签拆出姓名与身份。
- 切片的前置条件写在调查动作上，入库时按授予的证据存进 `evidence_dependency`；
  授予同一证据的动作前置不一致时拒绝导入。
- 一次性效果键沿用 W1 格式 `present:NPC01:E01`。
- 提问不建 `conversation` 表，返回 `fixed_reply`，记为 NOOP 请求；出示结果也直接带 `fixed_reply`。
  `NpcView` 暂时增加 `fixed_statement` 与 `presented_evidence_ids`，对话表在 v0.3 加入后再收回。
- `SessionView` 直接包含指控候选；指控草稿接口属于 v0.3（T12），本版没有。
- 正式指控缺字段返回 422 `VALIDATION_ERROR`，未使用 `ACCUSATION_INCOMPLETE`；解释上限沿用领域模型的 4000 字。
- 未实现 HTTP 限流（429 `RATE_LIMITED`）。
