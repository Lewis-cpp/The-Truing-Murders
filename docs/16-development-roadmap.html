01 /范围、容量与止损线

交付范围不变

1 个人工审核、固定版本的案件；4 NPC、4 场景、12 条证据（5 条关键）、3 条逻辑谎言链，至少 1 条包含两层秘密。完成探索、审讯、出示、人物关系图、时间线、结构化指控、三类判定、固定复盘、自动保存与继续。

多层链是对第 08 篇设计的实施安排；3 条链不等于仅有 3 条 lie_rule。压力、信任和四种情绪由程序规则控制。

容量假设

1 × 20 小时 × 约 14 周 ≈ 280 小时，另留 1 周缓冲（W15）。每个版本的估时已含约 20% 的返工余量；任务按 S（约 6 小时）、M（约 10～12 小时）、L（约 14～18 小时）初估，开工时再拆成 2～4 小时的小项。

团队版的 800 人时里，约 240 人时用于联调和交叉评审，一人开发没有这部分协调成本；其余差距靠下方的简化项消化，不靠删测试。实际投入明显少于 20 小时/周时按比例顺延，不压缩门槛。

当前起点：v0.1 已交付（见 W1 交付记录）：离线 CLI 切片、领域规则、静态预期和 CI。仓库已拆为 backend/ 与 frontend/ 两个独立子项目。沿用第 15 篇分层单体和 PostgreSQL；第 09～12 篇的 21 张表随用例分批落地。
一人开发相对团队版的调整：保留所有安全与正确性要求，只改变工作方式和非必要的规模。
事项团队版一人版

交叉评审每项任务由另一成员评审CI 全绿 + 自查清单 + 隔天复审自己的 diff；可另用 AI 代码审查补位

性能5 并发会话基准与多轮复验v0.6 用一个脚本测 5 会话非 AI P95，记录环境与样本

固定边界：LLM 只表达获准内容；Host 与 Review 默认固定文本；4 个 NPC 共用一个 Gateway，不做自主讨论。范围外：自动生成案件/关键线索、向量 RAG、Redis、消息队列、WebSocket、多玩家、账号平台、语音、第二案件和拖拽推理板。

《停电之夜》离线 CLI 切片：1 场景、1 NPC、3 条证据、1 条单层谎言、结构化指控、三类判定与固定复盘；全案草稿列出真相、知识权限和评分。无 Agent、无模型调用、无数据库，进度只在内存。

W2～3 · 把切片变成可保存的网页游戏

v0.2 · 约 40 小时
目标
通过真实 API 和数据库运行 W1 切片，支持刷新、重启与继续。前端使用默认组件样式。
实现模块
SQLAlchemy、Alembic、具体 Repositories、Case 离线导入、Game 与 Save/Load；只落地切片用到的静态定义、会话、证据、NPC、请求、效果和指控表。FastAPI /api/v1 的访客、开局、调查、固定审讯、出示、指控和恢复接口；Vue 最小功能页。Cookie/Origin、归属、幂等键和版本检查随写接口实现。
可演示成果
浏览器开局 → 取证 → 出示并获得固定回应 → 刷新继续 → 指控与复盘；重启后端后进度仍在。重开创建独立新局，旧局只读。
测试
在 PostgreSQL 验证迁移、复合引用、唯一效果和唯一结案；写证据后故障应全回滚。同键重发、同键异载荷、跨访客访问均有检查。不用 SQLite 代替锁测试。
主要风险
一个人同时写前后端容易两头半成品。先固定最小 DTO 并写 API 测试，后端闭环后再接页面；避免同时保存关系表与另一份可写完整 JSON 存档。
门槛：干净环境能迁移、导入并启动；重启可续玩，数据库失败不能显示保存成功。 任务 T06～T09

W4～6 · 完成整个案件的确定性闭环

v0.3 · 约 60 小时
目标
4 NPC、4 场景、12 条证据和 3 条谎言链全部接入，证明无 AI 仍可破案。该版本是接入真实模型的前置门槛，也是之后所有故障的回退基线。
实现模块
完整 EVENT → 击破 → 承认披露 → 一次 PROGRESS，以及独立 JUDGE；至少一条链含两层秘密。六个持久阶段、固定 Host/Review、conversation/message、指控草稿与冻结判定。补齐玩法 API；前端完成四角色固定审讯、证据详情、关系/时间线基础列表及完整指控复盘。
可演示成果
调查全案，演示“击破但未承认”和分层承认；保存草稿后返回调查，再正式结案。分别展示正确、部分正确、错误判定，以及不触发任何 NPC 承认仍正确结案的路径。
测试
12 条证据可达，5 条关键证据存在合法路径；正序、逆序、重复出示不越层、不重复加压。打乱同阶段规则数组仍得到相同业务结果；覆盖六阶段动作权限、GET 无副作用、图表投影不剧透、结案冻结。
主要风险
内容循环依赖、分层求值和心理阈值冲突；自己写预期又写实现，容易让预期迁就代码。先补完案件并提交人工预期，再写规则；先修案件配置和规则，不允许模型临时补线索。
门槛：完整固定模式、三类评分与无招供正确路径全部通过，才接入模型。打 v0.3 标签作为回退基线。 任务 T10～T14

W7～8 · 只接入一个 NPC 的 AI

v0.4 · 约 40 小时
目标
在一条已验证谎言链上接入自由文本审讯、授权上下文和固定降级。其他三个角色保持固定回复，整案继续可玩。
实现模块
Memory/上下文构建、最小 Agent Manager、Conversation Service、唯一 LLM Gateway 与生成编排；新增 llm_attempt。最近最多 6 个完整轮次，按披露权限筛选知识。业务先提交，模型在事务外调用；严格输出协议、额度预留、一次命令最多一次调用、30 秒整体时限初值、显式有界重试、迟到失效和 HTTP 轮询。先接一个供应商。
可演示成果
自由提问得到角色化回复；明确出示反证后，固定结果先显示，AI 再表达已获准内容。注入超时或无效输出后显示固定回复，证据和承认保留；重试只补对白。
测试
最终 messages 无本人锁定秘密和其他 NPC 秘密标记。假模型输出“发证据/认罪”、actions 或工具指令不能改状态。覆盖超时、429、截断、额外字段、空输出、额度不足、重复重试和迟到；未知用量不记零。少量真实样本人工复核，设硬预算。
主要风险
泄密、透明重试重复收费、模型等待占住事务。秘密在调用前过滤，关闭 SDK 自动重试。模型凭据或预算未到位时继续推进 v0.6 的非 AI 部分，不跳过本版门槛。
门槛：单角色正常、诱导、失败和迟到路径通过；业务结果与固定模式一致，才扩展四角色。 任务 T15～T18

W9～10 · 扩展四角色与会话记忆

v0.5 · 约 40 小时
目标
四 NPC 共用一套生成实现，同时保持知识、历史、秘密和承认状态隔离。长对话、角色切换及重开均不污染事实。
实现模块
角色配置与路由；最近消息、程序摘录摘要、结构化 NPC 状态三层 Memory；新增 npc_memory_summary，目标共 21 表。memory_epoch、摘要来源和修订条件写入。预算初值：输入 4,000 / 输出 400 tokens，历史加摘要 1,100 / 摘要 300。备用路由视余量决定。
可演示成果
轮流审讯四人，同一问题体现角色差异；一人承认不会变成其他人的知识。连续 30 轮后仍保留已承认事实；重启可继续，新局不继承旧记忆。达到额度后转为固定回复，仍可调查和结案。
测试
检查四角色各自披露状态；共享 Client 跨会话并发不混 messages。可控模型跑 100 轮，检查摘要缺失/过期/伪造来源、承认后旧否认失效、超预算降级。候选违规、最终可见违规与程序越权分别统计。
主要风险
共享消息混入、过期摘要污染、费用上涨。调用显式传入局与角色，承认每轮从数据库重建；默认 CI 使用假传输，真实评测设置硬预算。
门槛：四角色可用、长对话有界、承认不回退。可复现的可见泄密必须修复，必要时对该交互使用审核固定台词。 任务 T19～T21

W11～12 · 收齐功能并验证可部署性

v0.6 · 约 40 小时

实现模块

04 /一人开发的工作方式与最终验收

每周节奏（约 20 小时）

  1. 开始（约 1 小时）：确认上周进度，选定本周要能演示的行为，先写人工预期或测试。
  2. 实现（约 15 小时）：按用例小步提交，每天结束前 CI 全绿；同时只做 1 项任务。
  3. 收尾（约 3 小时）：干净环境启动，跑全部检查，隔天复审自己的 diff，更新 README 与限制记录。
  4. 余量（约 1 小时）：处理阻塞或回顾估时；连续两周超时就在版本边界重估范围。

“可运行”的统一定义

  • 有启动命令、依赖、样例案件和配置说明；v0.1 为交互 CLI，v0.2 起为网页/API/数据库。
  • 演示调用实际规则；固定对白属于正式降级能力，不能伪造证据和判定。
  • 保留此前能力；v0.2 起存档恢复有验证，后续迁移不以默认清库掩盖问题。
  • 发布记录包含代码、案件、规则、迁移版本、检查结果与限制；失败/未实现不算通过。

自查清单（替代交叉评审）

  • CI 两个任务全绿：后端 Ruff + pytest，前端格式、类型、lint、测试、构建。
  • 行为变更有回归测试；人工预期早于实现提交，未被实现反向修改。
  • diff 隔天重读一遍：权限、事务边界、模型输出能否改状态、前端是否拿到秘密。
  • README、配置、迁移说明同步；凭据和生成报告不入库。

分支与发布

  • 每个任务一个短分支，合并后删除；同一时间只开 1 个 PR。
  • 每个版本结束打标签（v0.2…v1.0），标签对应可从零启动的状态。
  • 门槛不过不进下一版；回退基线始终是最近一个通过门槛的标签。
  • 用 GitHub Issue 记录 T06～T27，Milestone 为所在版本。
门槛可核验标准版本
规则与内容关键证据可达；三结局、无招供正确路径；无反证不得承认，已承认不回退。v0.1 切片 → v0.3 全案 → v1.0 回归
存档与授权重复效果、半提交、跨局越权为 0；结案唯一；恢复不重跑规则或自动重发模型。v0.2 基础 → v0.4 生成一致性 → v0.6/v1.0 演练
AI 边界最终 messages / 响应无后台越权披露；模型无状态写入口；只有验证后的候选可见。可复现文本泄密先修复再启用。v0.4 单角色 → v0.5 四角色 → v1.0 题集
性能与成本记录 5 会话非 AI P95（目标 ≤1 秒）、模型等待与每轮用量。未知 token 单列；价格按实施时配置，不预填未经核实费用。v0.4 计量 → v0.6 基准 → v1.0 复验
