01 /范围、工时与团队分工

8 周交付范围

1 个人工审核、固定版本的案件；4 NPC、4 场景、12 条证据（5 条关键）、3 条逻辑谎言链，至少 1 条包含两层秘密。完成探索、审讯、出示、人物关系图、时间线、结构化指控、三类判定、固定复盘、自动保存与继续。

多层链是对第 08 篇设计的实施安排；3 条链不等于仅有 3 条 lie_rule。压力、信任和四种情绪由程序规则控制。

容量假设与止损线

5 × 20 小时 × 8 周 ≈ 800 人时。每周约 70 人时用于实现和模块自测，另留约 30 人时用于联调、交叉评审及返工。每项任务按 M（约 12～16 人时）初估，周一再拆成半天至一天的小项。

假设团队有 Python、SQL、基础前端能力，W2 有数据库环境，W4 前具备模型凭据和预算。实际投入明显少于 20 小时/人/周时应重估范围，不能通过删除测试维持日期。

当前起点：现有文档中的案件片段不能直接当作完整可发布剧本，W1 必须补内容与人工标准答案。沿用第 15 篇分层单体和 PostgreSQL 建议；第 09～12 篇最终为 21 张表，随用例分批落地。早期整局可写 JSON 方案不另做一套。
A～E 为学生占位名；每人负责实现与自测，E 负责跨模块验收，不包办所有测试。
成员主要责任前期 → 后期评审搭档
A · 案件与规则Case / Rule / Evidence / 评分配置内容与可解路径 → 四角色台词、图表内容、复盘解释C 查规则，E 查独立答案
B · 持久化与用例Game / Save/Load / Repositories / 迁移原子存档 → 生成落库、摘要持久化、部署恢复C 查事务，E 注入故障
C · 状态、API 与 AIState Machine / API / Memory / Gateway先写状态与 HTTP → W4 单 NPC → W5 四角色复用B 查并发，A 查授权
D · 客户端与交互CLI / Vue / TypeScript / Element Plus / EChartsW1 入口，W2～6 功能页面 → W7 主题与动效E 查操作，C 查接口
E · 测试与集成独立预期 / CI / 实库 / API / E2E / 验收持续集成 → 安全评测、性能与发布证据由另一成员复核结果

固定边界：LLM 只表达获准内容；Host 与 Review 默认固定文本；4 个 NPC 共用一个 Gateway，不做自主讨论。范围外：自动生成案件/关键线索、向量 RAG、Redis、消息队列、WebSocket、多玩家、账号平台、语音、第二案件和拖拽推理板。

03 /每周目标、模块、演示、测试与风险

第 1 周 · 证明核心玩法可以运行

v0.1 · 可玩的命令行切片
目标
确定正式案件的真相、知识权限、证据依赖与评分草稿；完成同一案件的最小可玩切片。第一周不开发 Agent、不调用模型。
实现模块
Case/Game 最小用例；domain/models.py、state_machine.py、evidence.py、rules.py；终端交互入口。切片包含 1 场景、1 NPC、3 条证据、1 条单层谎言与结构化评分。建立 pyproject、Ruff、pytest 和 README，只创建当前用到的文件。
可演示成果
终端开局 → 自主选择调查动作取证 → 进入审讯并明确出示 → 固定回复显示击破/承认 → 选择凶手、凶器、动机和过程 → 查看判定。错误答案也能正常结案。本周使用内存状态，退出即丢失，入口明确说明。
测试
人工独立填写正确、部分正确、错误预期；检查无反证不承认、非法阶段无副作用、重复证据不重复收益、数值上下界及结案冻结。案件引用缺失和阻断通关的循环依赖必须被发现。CI 运行格式、lint 和领域检查。
主要风险
剧本不可解，或整周只有文档。A/E 先手工走通全案草稿的关键证据路径与无招供正确路径，再落实切片配置；D 从周中接真实规则，不能以打印预写结果代替可玩版本。
周末门槛：无网络、无模型密钥可运行切片；规则和评分有可重复检查。完整剧本此时仍是草稿，不声称全案已实现。 任务 T01～T05

第 2 周 · 把切片变成可保存的网页游戏

v0.2 · HTTP + 真实数据库 + 基础页面
目标
通过真实 API 和数据库运行上周切片，支持刷新、重启与继续；审核完整案件配置。前端使用默认组件样式。
实现模块
SQLAlchemy、Alembic、具体 Repositories、Case 离线导入、Game 与 Save/Load；逐步落地静态定义、会话、证据、NPC、请求、效果、事件和指控等表。FastAPI /api/v1 的访客、开局、调查、固定审讯、出示、指控和恢复接口；Vue 最小功能页。Cookie/Origin、归属、幂等键和版本检查随写接口实现。
可演示成果
浏览器开局 → 取证 → 出示并获得固定回应 → 刷新继续 → 指控与复盘；重启后端后进度仍在。重开创建独立新局，旧局只读。本周保证切片网页闭环，完整内容在 W3 验收。
测试
在 PostgreSQL 验证迁移、复合引用、唯一效果和唯一结案；写证据后故障应全回滚。同键重发、同键异载荷、不同键同版本并发、跨访客访问均有检查。执行 API 切片并比较恢复前后状态，不用 SQLite 代替锁测试。
主要风险
数据库、接口和前端互相等待。B/C 周一固定最小 DTO，D 用契约样例开发、周中接实 API。迁移与案件导入独立执行；避免同时保存关系表与另一份可写完整 JSON 存档。
周末门槛：干净环境能迁移、导入并启动；重启可续玩，数据库失败不能显示保存成功。 任务 T06～T10

第 3 周 · 完成整个案件的确定性闭环

v0.3 · 完整案件，全部固定回复
目标
4 NPC、4 场景、12 条证据和 3 条谎言链全部接入，证明无 AI 仍可破案。该版本是接入真实模型的前置门槛。
实现模块
完整 EVENT → 击破 → 承认披露 → 一次 PROGRESS，以及独立 JUDGE；三条链中至少一条含两层秘密。六个持久阶段、固定 Host/Review、conversation/message、指控草稿与冻结判定。补齐玩法 API；前端完成四角色固定审讯、证据详情、关系/时间线基础列表及完整指控复盘。
可演示成果
调查全案，演示“击破但未承认”和分层承认；保存草稿后返回调查，再正式结案。分别展示正确、部分正确、错误判定，以及不触发任何 NPC 承认仍正确结案的路径。
测试
12 条证据可达，5 条关键证据存在合法路径；正序、逆序、重复出示不越层、不重复加压。打乱同阶段规则数组仍得到相同业务结果；覆盖六阶段动作权限、GET 无副作用、图表投影不剧透、结案冻结。浏览器跑完整路径，API 覆盖三结局与无招供路径。
主要风险
内容循环依赖、分层求值和心理阈值冲突。先修案件配置和规则，不允许模型临时补线索；文档中的录像例和实验室例是独立示例，不能直接拼接成正式案件。
周末门槛：完整固定模式、三类评分与无招供正确路径全部通过，才允许 W4 启用模型。保留 v0.3 为后续故障回退基线。 任务 T11～T15

第 4 周 · 只接入一个 NPC 的 AI

v0.4 · 单角色受限表达
目标
在一条已验证谎言链上接入自由文本审讯、授权上下文和固定降级。其他三个角色保持固定回复，整案继续可玩。
实现模块
Memory/NPCContextBuilder、最小 Agent Manager、Conversation Service、唯一 LLM Gateway 与生成编排；新增 llm_attempt。最近最多 6 个完整轮次，按披露权限筛选知识。业务先提交，模型在事务外调用；实现严格输出协议、额度预留、一次命令最多一次调用、30 秒整体时限初值、显式有界重试、迟到失效和 HTTP 轮询。
可演示成果
自由提问得到角色化回复；明确出示反证后，固定结果先显示，AI 再表达已获准内容。注入超时或无效输出后显示当前状态固定回复，证据和承认保留；重试只补对白。切换角色后旧回应不进入新角色对话。
测试
检查最终 messages 无本人锁定秘密和其他 NPC 秘密标记。假模型输出“发证据/认罪”、actions 或工具指令不能改状态。覆盖超时、429、截断、额外字段、空输出、额度不足、重复重试和迟到；未知用量不记零。做少量真实正常/攻击样本人工复核。
主要风险
泄密、透明重试重复收费、模型等待占住事务。秘密在调用前过滤，关闭 SDK 自动重试；固定结果独立展示。供应商协议不兼容时保留固定模式并验证替代配置，不降低权限检查。
周末门槛：单角色正常、诱导、失败和迟到路径通过；业务结果与固定模式一致，才放行四角色扩展。 任务 T16～T20

第 5 周 · 扩展四角色与会话记忆

v0.5 · 四 NPC AI + 有界 Memory
目标
四 NPC 共用一套生成实现，同时保持知识、历史、秘密和承认状态隔离。长对话、角色切换及重开均不污染事实。
实现模块
角色配置与路由；最近消息、程序摘录摘要、结构化 NPC 状态三层 Memory；新增 npc_memory_summary，目标共 21 表。实现 memory_epoch、摘要来源和修订条件写入。采用文档预算初值：输入 4,000 / 输出 400 tokens，历史加摘要 1,100 / 摘要 300。主备路由、容量、冷却与有界清理沿用第 13 篇，不在失败请求中自动追加换模调用。
可演示成果
轮流审讯四人，同一问题体现角色差异；一人承认不会变成其他人的知识。连续 30 轮后仍保留已承认事实；重启可继续，新局不继承旧记忆。达到额度后转为固定回复，仍可调查和结案。
测试
检查四角色各实际披露状态；共享 Client 跨会话并发不混 messages。可控模型跑 100 轮，检查摘要缺失/过期/伪造来源、承认后旧否认失效、必需上下文超预算降级。主备分别验证协议和预算。候选违规、最终可见违规与程序越权分别统计。
主要风险
共享消息混入、过期摘要污染、费用上涨。调用显式传入局与角色，承认每轮从数据库重建；摘要不能授权。默认 CI 使用假传输，真实评测设置硬预算，不增加模型摘要或 NPC 间传播。
周末门槛：四角色可用、长对话有界、承认不回退。可复现可见泄密必须修复，必要时对该交互使用审核固定台词。 任务 T21～T25

第 6 周 · 收齐功能并验证可部署性

v0.6 · 完整 MVP，视觉保持朴素
目标
补齐关系图、时间线和恢复交互，在演示环境交付完整基础版。周末冻结新增玩法，为美化与发布留出时间。
实现模块
ECharts 已知关系图、来源详情与等价列表；保留精确/区间/未知时间及矛盾证词的时间线；指控步骤、证据关联、复盘联动。静态前端 + 单异步后端进程 + PostgreSQL 的部署、备份与恢复；固定 AI 题集及脱敏用量报告。
可演示成果
部署环境开局 → 取证 → 四人审讯/出示 → 查看关系和时间矛盾 → 刷新继续 → 指控复盘。演示模型离线、提交结果未知后查原请求、服务重启和备份恢复。图表完成推理辅助，本周不做主题和装饰动效。
测试
全量离线回归与浏览器三结局、无招供、恢复路径；前端构建和图表响应无隐藏资料。5 并发会话测非 AI P95，目标 ≤1 秒并记录环境、样本。演练事务失败、COMMIT 后断线、模型发出后崩溃、旧局迟到和数据库恢复。
主要风险
部署差异、图表泄露隐藏节点、补功能挤压验收。周中部署；图表只消费后端授权投影。优先修既定功能，不加 SSE、第二案件或拖拽推理板。
周末门槛：FR-01～19 均有实现和验收证据，完整 MVP 可部署。若教学周期只有 6 周，可交付此朴素基础版，但未完成验收必须列明，不宣称已达到 v1.0。 任务 T26～T30

第 7 周 · UI 美化与可用性修正

v0.7 · 候选演示版
目标
功能冻结后统一“侦探档案工作台”视觉，提升阅读和操作效率。美化不改变规则、知识权限和存档语义。
实现模块
Element Plus 主题变量、排版、间距、响应式布局、图表图例；Loading/Error/Fallback、草稿保存和空状态文案。仅用 CSS/Vue 加短动效，支持减少动效。补焦点、键盘、图表列表；其他成员处理既有安全、恢复和模型评测缺陷。
可演示成果
约 6 分钟演示：开局、取证、反证改变说法、关系/时间矛盾、刷新与模型降级、指控复盘。邀请 3～5 名非开发同学试用，记录卡点及是否混淆对白和事实。
测试
1366×768、1920×1080、窄屏、200% 缩放；键盘完成核心路径，文字对比度目标 4.5:1，状态不只靠颜色。关闭动效后功能完整；慢网/连点/保存中继续编辑不丢数据。运行受影响 E2E，主备题集复测并报告样本和费用。
主要风险
改布局破坏交互，装饰误导结果。只在服务端确认后显示成功，不伪造 AI 裁决进度。优先修试用阻塞；立绘与额外动画可裁减，B/C/E 同时复核可靠性。
周末门槛：核心路径可用键盘完成；试用阻塞、可复现泄密和丢档问题关闭。未完成装饰不挤占安全与恢复验收。 任务 T31～T35

第 8 周 · 发布、复验与答辩交付

v1.0 · 可复现交付版
目标
冻结代码、案件、规则、迁移与模型模板版本；在干净机器复现安装和通关。只修验收缺陷，不新增功能。
实现模块
发布配置、README 启动/迁移/导入/检查命令、无密钥环境示例、故障切换说明、测试与模型评测报告、需求追踪表、演示脚本和交付清单。A 内容讲解；B 部署恢复；C AI 配置；D 前端构建；E 总验收。
可演示成果
另一名同学只按 README 从零启动，分别在正常 AI 与关闭 AI 模式下完成正式案件；恢复备份后继续未结案存档。准备错误/部分正确结果及正常/断网两套答辩路径，交付版本清单和已知限制。
测试
运行所有已定义格式、lint、类型、构建和测试命令；第 14 篇 P0 矩阵全过，无未解释 skip/xfail。复查四角色隔离、三结局、无招供、幂等、六阶段权限、重启/备份恢复和 5 会话性能。真实模型结果人工复核，未验证路由不启用。
主要风险
临时换模型、环境不可用、最终合并回归。周初冻结候选版，每次修复补回归；模型或 Prompt 改动重测。准备固定回复配置与可恢复存档，禁止强制通关或前端授予证据。

04 /每周交付方式与最终验收

固定一周节奏

  1. 周一：确认上周门槛、本周演示、DTO 与人工预期；每人最多 1 项进行中。
  2. 周二～三：按用例实现并自测，小 PR 持续合并；D 接实 API，E 持续集成。
  3. 周四：停止加范围，联调、实库/浏览器检查、故障复现与交叉评审。
  4. 周五：干净环境启动，演示、运行检查、打标签，记录限制与下周调整。

“可运行”的统一定义

  • 有启动命令、依赖、样例案件和配置说明；W1 为交互 CLI，W2 起为网页/API/数据库。
  • 演示调用实际规则；固定对白属于正式降级能力，不能伪造证据和判定。
  • 保留此前能力；W2 起存档恢复有验证，后续迁移不以默认清库掩盖问题。
  • 发布记录包含代码、案件、规则、迁移版本、检查结果与限制；失败/未实现不算通过。
