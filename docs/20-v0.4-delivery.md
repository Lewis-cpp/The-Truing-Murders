## 配置方法

环境变量（`.env.example` 有默认值，默认关闭；真实密钥不入库）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `LLM_ENABLED` | `false` | 关闭时与 v0.3 完全一致（`GENERATION_DISABLED`） |
| `LLM_ENABLED_NPCS` | `["NPC01"]` | 仅列表内角色走模型 |
| `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY` | 空 | 启用时三者缺一启动失败，不静默降级 |
| `LLM_TIMEOUT_SECONDS` | `30.0` | 整轮时限，从受理起算 |
| `LLM_MAX_INPUT_TOKENS` / `LLM_MAX_OUTPUT_TOKENS` | `4000` / `400` | 输入预算按字符估算（内容字符数 + 每条消息 4） |
| `LLM_SESSION_CALL_LIMIT` / `LLM_SESSION_TOKEN_LIMIT` | `60` / `200000` | 单局硬预算，开局写入 `llm_budget_json`，整局不变 |
| `LLM_CONCURRENCY` | `4` | 进程内同时在途的模型调用（有界线程池） |

调用数按所有非 `NOT_SENT` 尝试汇总；token 按已知用量加未知的预留累计，未知用量绝不记零。
额度不足时零调用直接固定回复，重试同样被 429 拒绝。

## 与设计文档的差异

- `conversation_message.attempt_id`（09 篇 6.5 已定义、v0.3 未建列）由迁移 0004 补建，
  消息可关联产生它的尝试；固定降级也记录导致降级的尝试。
- 供应商 `Retry-After` 冷却暂存于该尝试的 `usage_json.retry_after_seconds`
  （09 篇 6.6 未为它设专用列）；`can_retry_reply` 与重试端点据此判断冷却。
- `billable_tokens` 按 `input_tokens + output_tokens` 记账（OpenAI 兼容口径的简化实现）。
- 09 篇 6.6 的 `pricing_snapshot_json`/`estimated_cost` 建列但本版不估值，恒为 NULL。
- 13 篇 5.1 的 `response_mode`、路由建议与备用模型未实现：v0.4 只有单模型 JSON Schema 一条路
  （备用路由按规格属 v0.5 视余量）。
- `retry-retries` 的幂等记录走既有 `action_request` 表（`command_type=REPLY_RETRY`），不建新表。

## 假传输覆盖的故障清单

网关层（`MockTransport` + 假 Gateway，全离线）：5xx 与 503、429（Retry-After 秒数/HTTP 日期/垃圾值）、
401/403、400 `context_length_exceeded` 与其他 400、404；连接失败与连接超时（未发出）、
读超时（已发出）、持续小块正文无法续命至整轮 deadline；响应体超过 64 KiB；
`choices` 非恰好一项、`tool_calls` 非空、`refusal`、`content_filter`、`finish_reason=length`；
重复键、NaN/Infinity、代码围栏、前后杂文、多余字段、类型不符、去空白为空、超过 1200 字符、
恰好 1200 字符通过；usage 缺失/负数/字符串/布尔/浮点一律视为未知；deadline 已过不发请求。

编排层（假 Gateway + 手动派发器）：正常生成、三种违规候选丢弃（秘密/状态声明/提示词复述）且不改状态、
六类失败降级映射、出示先返回固定结果、他人保持固定回复、同一时刻一次生成（409）、
切换/离开/指控致 STALE 且迟答只结算、切换后迟答不泄露、预算耗尽零调用并阻断重试、
过期占位清理不重发、派发后崩溃记 UNKNOWN、读取与重放不派发、关闭生成时逐字节等同 v0.3 固定模式、
重试链成功填充同一消息槽且至多两次。
