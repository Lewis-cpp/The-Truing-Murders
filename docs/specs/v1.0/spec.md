# v1.0 规格：美化、可访问性与发布

任务 T25～T27，约 40 小时 + W15 缓冲。前置：`v0.6` 标签，新增玩法已冻结。
依据：第 11 篇第 7～8 节、第 14 篇第 14 节、NFR-08、路线图 v1.0。

## 1. 目标

统一“侦探档案工作台”视觉，提升阅读和操作效率；在全新环境按 README 复现安装和通关（AI 开启、关闭各一次）；
交齐测试报告、模型评测报告、需求追踪表和已知限制。**美化不改变规则、知识权限和存档语义。**
W15 只修缺陷，不加功能；每个修复都补回归测试。

### 不做

新玩法、新端点、新数据表（迁移只允许修缺陷）、立绘和额外动画（进度不足时第一个裁掉）、外部试用（可选）、
更换模型或 Prompt（如必须更换，重跑 v0.4/v0.5 的全部评测）。

## 2. 视觉与交互（T25）

- 主题：`frontend/src/styles/theme.css` 用 Element Plus CSS 变量定义颜色、字号、间距；
  定义 `--tm-motion-duration`（默认 `180ms`），所有过渡和动画只用这个变量；
  `@media (prefers-reduced-motion: reduce)` 下为 `0ms`。
- 布局：≥1200px 三栏（场景/证据 · 审讯 · 关系与时间线），768～1199px 两栏，<768px 单栏 + 标签切换（默认显示“场景”标签，进入审讯后自动切到“审讯”）。
  任何宽度和 200% 缩放下都不能出现横向滚动条（`document.documentElement.scrollWidth <= clientWidth`）。
- 状态与反馈：Loading、空状态、错误、降级（固定回复）都有文字；成功提示只在服务器确认后出现；
  `role="status"`（`aria-live="polite"`）播报操作结果，错误用 `role="alert"`。
- 不只靠颜色：情绪、承认进度、证据可信度、时间线标记、判定类别都有文字标签。
- 键盘：所有操作都能用 Tab/Shift+Tab/Enter/Space 完成；焦点样式可见；打开详情或对话框后焦点进入其中，
  关闭后回到触发按钮。
- 对比度：正文与按钮文字至少 4.5:1（以 axe-core 的 `color-contrast` 规则为准）。
- 依赖：前端 dev 组加入 `axe-core`（固定版本），只在测试中使用，不进入构建产物。

## 3. 试用（T26，可选）

邀请 2～3 名玩家，记录卡点、是否混淆“对白”和“事实”、是否发现泄密或丢档。阻塞问题、可复现泄密和丢档必须关闭，
每个修复都有回归测试。没有试用就在交付记录中写“未进行”，不能编造反馈。

## 4. 发布总验收（T27）

1. 在全新容器或虚拟机里只按 README 从零启动（克隆 → 安装 → 数据库 → 迁移 → 导入 → 前后端 → 部署版），
   AI 关闭与开启模式各完成一次正式案件，记录命令输出与截图位置。
2. 运行全部已定义检查：后端格式、lint、pytest、`alembic check`、E2E、性能；前端格式、类型、lint、测试、构建；
   真实模型评测（有凭据与预算时）。
3. 第 14 篇 P0 矩阵逐项对照，结果写进 `docs/test-report.md`：通过、未通过、未执行分别列出，不允许把未执行写成通过。
4. 更新 `docs/traceability.md` 到最终状态；`docs/23-v1.0-delivery.md` 写明版本（代码、案件、规则、迁移、Prompt）、
   命令、证据、已知限制。
5. 无未说明的 `skip`/`xfail`；仓库里没有凭据、生成报告或数据库备份。
6. 全部满足后打 `v1.0` 标签；存在阻断问题时保留候选版并如实说明，不能把一次演示成功当作验收通过。
